# V17 — Cloud Deployment + Production Monitoring

## Goal

V17 moves the V15/V16 Dockerized CV Analyzer from localhost to a public cloud deployment.

Target architecture:

```text
                    Internet
                       |
                       v
             +---------------------+
             | Render Frontend     |
             | React + Nginx       |
             +---------------------+
                       |
                       | HTTPS API requests
                       v
             +---------------------+
             | Render API          |
             | FastAPI + Uvicorn   |
             +---------------------+
                       |
                       | PostgreSQL
                       v
             +---------------------+
             | Render Postgres     |
             +---------------------+
```

## Why Render

Render supports Docker-based web services and Git-connected deployments.
It also supports Blueprint infrastructure-as-code through `render.yaml`.

The API uses `/health` for an application-level health check.

The Blueprint uses:

```yaml
autoDeployTrigger: checksPass
```

so the Render service can be configured to deploy only after GitHub CI checks pass.

## Files added

```text
render.yaml
docs/V17_CLOUD_DEPLOYMENT.md
```

No real secret is stored in the repository.

## Important security behavior

`JWT_SECRET` is generated by Render.

`GEMINI_API_KEY` is marked with:

```yaml
sync: false
```

so the real key must be entered through the Render dashboard / Blueprint setup.

`VITE_API_BASE_URL` is also a deployment-time value and must contain the public API URL.

Never commit:

```text
.env
.env.*
JWT secrets
Gemini API keys
database passwords
```

## Deployment steps

### 1. Open Render

Go to:

https://render.com/

Sign in with GitHub and connect the repository:

```text
AdhyanSharma/cv-analyzer
```

### 2. Create the Blueprint

From the Render dashboard choose:

```text
New
→ Blueprint
```

Select the GitHub repository and branch:

```text
main
```

Render should detect:

```text
render.yaml
```

The Blueprint defines:

```text
cv-analyzer-api
cv-analyzer-frontend
cv-analyzer-db
```

### 3. Configure the API secret

When Render asks for:

```text
GEMINI_API_KEY
```

enter your real Gemini key through the Render secret/environment-variable interface.

Do NOT put it into `render.yaml`.

Render generates `JWT_SECRET` automatically.

### 4. Deploy the database + API

Wait for the API service to finish deploying.

The API should expose a URL similar to:

```text
https://cv-analyzer-api.onrender.com
```

The exact hostname is assigned by Render and may differ.

Test:

```text
https://YOUR-API-URL/health
```

Expected response:

```json
{
  "status": "ok",
  "service": "cv-analyzer-api",
  "version": "v15"
}
```

### 5. Configure the frontend API URL

The frontend environment variable must be:

```text
VITE_API_BASE_URL=https://YOUR-API-URL
```

Do not add a trailing slash unless the frontend API client specifically expects one.

Then deploy/redeploy the frontend.

### 6. Open the frontend

Render provides a public URL similar to:

```text
https://cv-analyzer-frontend.onrender.com
```

The exact hostname is assigned by Render.

Open the frontend and test:

```text
Register
Login
Job creation
Candidate upload
Candidate 360
Explainability
Evaluation / audit
```

## Port behavior

The current project Docker images use:

```text
API:      8000
Frontend: 80
```

The Blueprint explicitly provides those `PORT` values.

Render web services must listen on `0.0.0.0`.
The current Dockerized project is designed to run its API on `0.0.0.0:8000`
and Nginx on port 80.

## Deployment order

Use this order when troubleshooting:

```text
1. PostgreSQL
2. API
3. Frontend
4. Browser smoke test
```

The frontend cannot successfully call the cloud API until
`VITE_API_BASE_URL` points to the deployed API URL.

## Auto-deployment

The Blueprint contains:

```yaml
autoDeployTrigger: checksPass
```

The intended production flow is:

```text
git push
   |
   v
GitHub Actions
   |
   +--> Backend tests
   +--> Frontend build
   +--> Docker validation
   |
   v
CI green
   |
   v
Render deployment
```

This creates a practical CI → CD chain for the portfolio project.

## Health monitoring

Render's health check for the API is:

```text
GET /health
```

Use `/health` as the simple liveness check.

For deeper troubleshooting, inspect:

```text
Render Dashboard
→ cv-analyzer-api
→ Logs
```

and:

```text
Render Dashboard
→ cv-analyzer-frontend
→ Logs
```

## First cloud smoke test

After deployment, verify these in order:

```powershell
# API
curl.exe https://YOUR-API-URL/health
```

Then open:

```text
https://YOUR-FRONTEND-URL
```

Then test login and a protected API request.

## Free-plan note

Render currently documents free web services and a free Postgres option,
but the free Postgres instance is documented as expiring after 30 days.
For a long-running portfolio demo, review the current Render plan limits
before relying on the free database for permanent availability.
